# レビュー作業室

virtualCrypto3を人間とLLMで確認するための、ローカル専用の小さなWebアプリです。
現在の実装・プロジェクト資料から整理した70件の判断項目を備えています。
項目ごとにCodexと会話し、確認の準備、仕様の相談、ソースの修正、テスト、再確認を進めます。
依頼と回答・変更差分・実行結果を残し、最後に人間が進捗を記録します。判断理由や根拠は必要に応じて残せます。

## 起動

必要なものはNode.js 24以上、Git、ログイン済みのCodex CLIです。
依存パッケージのインストールやAPIキーのアプリへの登録は不要です。
Codexがなくても、進捗管理と依頼文のコピーは利用できます。

```sh
codex login       # 未ログインの場合のみ
just review
# または
npm --prefix tools/review-workbench start
```

ブラウザで <http://127.0.0.1:4317> を開きます。終了はCtrl+Cです。
既存の本体サーバー、Discordの登録、本番DBは起動時に操作しません。

## 使い方

1. 分野・進捗・重点項目・検索で、確認したい項目を選びます。
2. 判断基準と参照ファイルを読みます。参照先は行番号付きで表示できます。
3. 「この項目を確認したいので準備して」などのメッセージを送ります。
4. 結果を見て「この挙動をこう修正して」「別の案にして」と続けて依頼します。
5. Codexがソース・テスト・文書を変更し、必要な検証を行います。仕様や判断に関する質問には画面から答えられます。
6. 会話中の差分・実行結果や「現在の変更を見る」で修正内容を確認します。追加修正や再確認も同じ会話で依頼できます。
7. 進捗を保存します。確認者・判断メモ・根拠は任意です。コードを修正してもチェックや進捗を自動的に戻しません。再確認したいときは会話で依頼したり、進捗を「確認中」に変更したりできます。

会話は項目ごとに自動的に継続します。相談から始めても、修正から始めても構いません。
判断フォームの記入や保存は送信の前提ではありません。編集中のメモは未確定と明示してCodexに渡します。
実行中や質問への回答待ちでも、メッセージを「キューに追加」できます。同じ項目・別の項目を問わず、送信した順に1件ずつ実行します。
画面上部の「送信待ち」で順番と内容を確認し、不要なメッセージを取り消せます。取り消す操作は実行中の作業に影響しません。
後続の依頼は、実行開始時点のコード・保存済みメモ・その項目の会話を使います。送信時の入力内容、編集中のメモ、実行範囲、新しい会話の指定も保持します。
待機中のメッセージはローカルに保存され、画面の再読み込みやアプリ再起動でも残ります。再起動後は自動で続行し、中断された作業自体は重ねて実行しません。
項目を移動しても編集中のメモとメッセージを画面内で保持します。保存前にページを閉じる場合は確認を表示します。
会話を再開できない場合はエラーを表示します。「新しい会話で始める」を選ぶと履歴を残して新しく開始できます。
依頼文はコピーして他のLLMやハーネスへ渡すこともできます。

実行範囲は依頼ごとに選びます。

| モード | 用途 |
| --- | --- |
| ローカル作業（承認なし） | 既定値。依頼された調査・修正・テスト・ローカルサーバーの起動・依存取得を、実行許可を毎回尋ねずに進めます。 |
| 読み取りのみ | 変更を加えずに調査や相談をしたい場合に指定します。 |

実行承認は`never`です。ローカル作業はCodexの`danger-full-access`を使い、手元の実行ユーザーの権限で動きます。
「読み取りのみ」を選んだ場合は、書き込みとネットワークを許可しないsandboxで動き、範囲外の操作は実行しません。
この依頼には本番デプロイ、実際の通貨の送金、Discordへの投稿、外部サービスへの書き込み、Git pushを含めません。
補助資料や使い捨ての確認用データには`.review-artifacts/<項目ID>/`を使えます。実装の修正先は通常のソースファイルです。
実行中に依頼を変更したい場合は「中断」して続きを送れます。中断しても実行済みの変更は残り、会話と実行記録から確認できます。
中断・失敗で現在の作業が終わった場合も、送信待ちがあれば次の依頼へ進みます。質問への回答待ちは現在の作業を継続し、後続を待機させます。

## 項目の範囲

| 分野 | 件数 | 人間が判断することの例 |
| --- | ---: | --- |
| Discord・画面 | 12 | 実画面、両端末、同意の分かりやすさ、操作結果の公開範囲 |
| 認可・同意 | 9 | 最小権限、無期限PAT、失効の境界、既存クライアントの前提 |
| 通貨・契約 | 9 | 発行ルール、同意と残高拘束、充当順、期限、削除の不可逆性 |
| 移植・互換性 | 7 | v2互換、意図した変更、旧資格情報、旧版との同居 |
| 外部連携 | 7 | 実Discord、署名とmTLS、配送保証、デモの実利用 |
| 運用・移行 | 12 | 実データの移行・復元、本番対象、負荷、監視、障害対応 |
| 仕様の判断 | 6 | 上限、待機時間、ミュート、自動更新の範囲、サポート |
| 説明・公開 | 4 | 日本語、API例、古い資料、秘密情報とライセンス |
| リリース判断 | 4 | 範囲の漏れ、対象コミット、Go/No-Go、切替後の観測 |

カタログは[`lib/catalog.mjs`](lib/catalog.mjs)です。各項目に判断したいこと、具体的な判断基準、
LLMに準備させる内容、参照ファイルがあります。
`docs/qa.md`のHuman・判断事項と、認可・移行・運用を含む13文書を横断しています。
古い資料のチェック済み記号や過去のCI成功を、人間の承認として自動入力しません。
新しい論点は画面から追加できます。`GO-01`は機能・資料と項目の対応を再点検するための項目です。
将来の変更まで自動で網羅されるわけではないので、この点検もレビューに含めます。

## 記録と再確認

- 進捗・判断履歴・Codexの会話ID・各メッセージ・変更差分・実行記録をローカルの`state.json`に保存します。
- 既定の保存先は`$XDG_STATE_HOME/virtualcrypto-review/<リポジトリ識別子>/`です。
  `XDG_STATE_HOME`がなければ`~/.local/state`を使います。保存先を本体のGit履歴から分けています。
- 識別子はリポジトリの絶対パスのハッシュです。別の場所のcloneは別の記録になります。
- 保存ディレクトリは所有者のみアクセス可、ファイルは所有者のみ読書き可で作成します。
- 同じ保存先のアプリを同時起動しません。複数タブの古い更新は409で拒否します。
- コードやコミットの更新で、判断済みの進捗・チェック・メモを無効にしたり、保存を拒否したりしません。
- 保存時の版と、各作業の開始・終了時の版を履歴として記録します。再確認するかどうかは人間が決めます。
- 起動中の作業がアプリ終了で失われた場合、次の起動で「中断」にします。完了として扱いません。
- データが壊れていたら上書きせず停止します。バックアップする場合はアプリを終了して保存ディレクトリをコピーします。
- Markdown/JSON出力は判断材料を共有するためのものです。LLMの出力や人間のメモも含むため、共有前に内容を確認してください。

進捗の完了数は、人間が記録した「確認済み」と「対象外」の件数です。コード更新で完了数を自動的に減らしません。
「保留」「要修正」は完了数に含みません。これは判断の記録であり、本番デプロイを許可するボタンではありません。
LLMの作業完了は「確認待ち」を表示するだけで、判断基準や人間の記録を変更しません。
会話内の差分はその作業についてCodexが報告したものです。「現在の変更を見る」は作業開始前からの変更も含む作業ツリー全体を表示します。

## 設定

| 環境変数 | 用途 |
| --- | --- |
| `REVIEW_PORT` | HTTPポート。既定は4317、常に127.0.0.1にbind。 |
| `REVIEW_REPO_ROOT` | 対象リポジトリ。既定はこのツールを含むリポジトリ。 |
| `REVIEW_DATA_DIR` | 保存先の上書き。Gitの外の専用ディレクトリを指定します。 |
| `REVIEW_CODEX_BIN` | Codex CLIの実行ファイル。既定はPATHの`codex`。 |

Codexのモデル・認証は既存のCLI設定を使います。アプリの認証情報をブラウザに返しません。
本体用の`VCRYPTO_*`や`DATABASE_URL`などをCodex子プロセスに引き継ぎません。
本番資格情報を会話や判断メモに貼り付けないでください。

## 実装と検証

Node標準ライブラリのみでHTTP・永続化・SSEと、[Codex App Server](https://developers.openai.com/codex/app-server)
のJSON-RPCを扱います。フロントはビルド不要のHTML/CSS/JavaScriptです。
Codex CLI **0.157.1**の生成スキーマでメソッドと承認形式を確認しています。
App Serverは変更されることがあるため、CLI更新時は接続と承認フローを再確認してください。

```sh
just review-check
# または
npm --prefix tools/review-workbench run check
npm --prefix tools/review-workbench test
```

CIはモデルを呼ばず、stdioのテスト用サーバーで承認なしの実行・質問・中断・異常終了・通知順序を検証します。
隔離したcheckoutで「調査→ソース修正→再確認→人間の判断」と会話の継続・記録の保持も検証します。
保存の整合性、コード変更検出、参照範囲、Origin/Host/CSRF、複数タブの更新競合も検証します。
このアプリは本体Dockerイメージに含めず、CIにもデプロイ処理を追加しません。
